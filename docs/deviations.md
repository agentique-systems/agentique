# Deviations from KerML 1.0 / SysML 2.0 (R-9)

Places where `crates/language` departs from the pinned standard, one line
each with its reason. The subset itself is in [subset.md](subset.md).

1. **Built-in library.** Only `ScalarValues` exists, built in, with the pinned qualified names; its types are `attribute def`s where the pinned KerML library declares `datatype`s. Reason: no runtime library bundle (R-4); the SysML equivalent of a data type is an attribute def.
2. **No implied library specialisations.** A part def does not implicitly specialise `Parts::Part`, an attribute `Base::dataValues`, and so on; rules use element kinds directly. Reason: the kinds carry the same meaning for the subset without loading the Systems library.
3. **`end port p` / `end part p`.** Accepted in connection and interface defs, and always printed with the keyword. Reason: the printed `OccurrenceUsagePrefix` omits `end`, but the specification's own examples (7.13.2, 7.15.1, 8.4.10.1) use it.
4. **`satisfy R by x;` without `assert`.** Accepted; `assert` is accepted and not printed. Reason: the printed `SatisfyRequirementUsage` production lost its optionality markers (`'assert' ( isNegated ?= 'not' )`), while 7.21.4 describes and shows `satisfy R by x;`.
5. **Lookup order.** Owned members hide inherited ones, and inherited ones hide imported ones; two different imported elements with one name are an ambiguity error; the same element imported twice counts once. Outward lookup ends at the document's own top-level members and imports, then all top-level members and the library. An import's own name is looked up without the other imports of the namespace that holds it. Reason: KerML treats inherited and imported memberships alike and leaves import collisions underspecified (KERML11-75); a fixed order is simple and ambiguity stays an error.
6. **Redefinition lookup.** `:>> x` searches only the features inherited by the owner, drops candidates redefined by another candidate, and reports several survivors as ambiguous; there is no fallback to enclosing scopes. Reason: KERML11-140 leaves this open; redefining something that is not inherited is almost always a mistake.
7. **Hiding an inherited feature is an error.** An owned feature named like an inherited feature must redefine it (`duplicate-name`). Reason: KerML only requires names to be distinguishable (a warning in the pilot); silently hiding a feature makes models hard to read.
8. **Port compatibility.** An untyped connection or interface between two ports requires every directed feature to meet a same-named feature of the opposite direction; what the sender sends must be the receiver's type or a specialisation of it. Connecting a port to a port of a part inside that port's part (`p` to `inner.p`, `sub.i` to `sub.inner.i`) passes items on, so there the directions must be the same; a chain through a reference counts by what the reference is bound to (a part bound outside, or a reference not bound, is outside, so the ports face each other). A typed connection requires each end to have the definition end's port type with the same conjugation. Reason: SysML does not constrain this, but "connections fit" is the model-validity promise.
9. **Part typing.** Every type of a part usage must be a part def (items: item or part defs). Reason: SysML allows extra non-part types beside one part def; the subset keeps one clear meaning.
10. **Literal value checks.** A literal is checked against a built-in scalar type as the most specific type its value allows (an integer as `Positive`, `Natural` or `Integer`; a real as `Real`). Reason: KerML defines no static check of feature values; this one catches plain mistakes such as a string for a number.
11. **Composition cycles are an error.** A part def must not contain itself through parts with a lower bound of at least 1 (a part without a multiplicity counts as required). Reason: KerML does not forbid it statically, but such a part could never be built, so "parts compose" rejects it.
12. **Built-in `Agents` library.** `Agents::Agent`, `AgentMode` and `AgentOutput` are Agentique's own library, not part of the SysML standard library, and `Agent` does not specialise `Parts::Part` (deviation 2). Reason: SysML has no AI concept; a library definition gives agents instance-level meaning that can be run and checked (C-42, ROADMAP §4.11).
13. **Built-in `Scenarios` library.** `Scenarios::StandIn` and `Outcome` are Agentique's own. Reason: SysML has no test-double concept for a part a verification case replaces; a library definition keeps stand-ins ordinary, typed model elements (C-50, ROADMAP §4.14).
14. **Durations without units.** `accept after d` takes `d` as milliseconds of logical time, a `Natural`. Reason: the ISQ and SI libraries are not loaded (R-4); one fixed unit keeps runs reproducible and simple.
15. **`then S;` only after `entry`.** It names a state machine's first state. After a state, `then S;` (and `accept … then S;`) is SysML's short form of a transition; it is reported as unsupported and written as `transition first … then S;` instead. Reason: one written form per transition keeps identities and editing simple.
16. **Action members run in the order written.** An action body's members run one after the other, and the printer writes `then` before each after the first, which is SysML's succession between them. Members read without `then` also run in written order, where SysML would let them start together. Reason: steps and effects are sequential in every scenario this phase needs.
17. **Named arguments are linked references.** In `new T(a = x)`, `a` is held as the feature chain `T.a`, linked by identity to the feature `a` of `T`, so renaming `a` carries through (D-1). Positional arguments are unsupported. Reason: the standard's argument binding by parameter redefinition has the same meaning; the link is how Agentique keeps it.
18. **A check holds where it stands.** An `assert constraint` among a scenario's steps is evaluated when the steps before it have run, with the values they received. Reason: a scenario's checks are about the outputs of its steps, and the order makes each check reproducible.
19. **A composite part is not bound to another part of the same owner.** `part store : Store; part primary : Store = store;` is reported `wrong-value`; write `ref part primary`. Reason: SysML allows a composite usage's value to be a composite value of the same featuring instance (7.6.3; a value of another owner it forbids itself), but such a binding names one part twice as if it were two parts, the duplicated-component mistake; `ref` makes the second name explicit.
