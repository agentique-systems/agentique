# Isolated effective-audit batch experiment

This branch measures whether resetting the same immutable query evaluator every 32 authored subjects causes avoidable repeated work. It is an experiment, not a production performance claim. Non-verification builds keep 32 subjects; verification builds accept only the explicit values 32, 128 and 256. Query context, dispatched operations, closure requirements and validation remain unchanged.

The reusable workflow is reached through the already registered `runtime-asset.yml` dispatch with `audit_batch_experiment=true`. It does not build Native Studio or helpers. The integration lead dispatches this branch with the existing runtime tag and transport digest required by that router.

The job authenticates the completed successful oracle run `36231357374`, its exact source commit `a6e1f41d2b549a8be10a79dfa3ec786c090b65b3`, artifact ID/name and independently pinned GitHub transport digest. It verifies the prior build, binary, invocation and successful exact-equivalence receipt before selecting only its checkpoint, source map and cold observation map. The pinned runtime bundle and each cache entry are checked separately; the executable still performs normal semantic publication authentication.

One ordinary release oracle is built from the experiment commit. Every trial restores identical checkpoint/source bytes in its own process, with the same executable and runtime inputs. The 32-subject trial must equal the prior passing cold oracle's entire observation map. Both larger trials must equal the 32-subject map. This includes canonical records, occurrences, derived facts and proof sets, identities, closure semantic digest, diagnostics, and all 29 applicable query operation families with values, completeness, reads and evidence. The only oracle normalization is the already documented fresh kernel revision label. Validation must independently pass.

The observer records process RSS/private/OS peak memory, host available memory and elapsed time every 250 ms. A live reserve guard or a 20-minute child deadline terminates only that trial's process tree and retains its failed evidence. The 256-subject trial additionally requires successful completion of 128 and conservative measured memory headroom. A skip is explicit. Observation maps are loaded for comparison only after the semantic child exits and are released before launching another child.

Compare `full_phases.effective_audit_micros` for the audit boundary, `full_compile_ms` and `cold_checkpoint_restore_ms` for the complete restore boundary, and `process.elapsed_seconds` for runtime authentication plus restoration, validation and full observation export. Whole-process memory includes observation export; do not attribute it solely to auditing. The checkpoint path does not exercise parent candidate reuse, so no result from this experiment alone establishes incremental candidate speedup.

The local checks in `audit-batch-experiment-local-checks.json` passed: five evidence regressions, Python compilation, workflow YAML and embedded Python parsing, workspace formatting and whitespace checks. Rust release compilation, semantic equivalence, elapsed time and peak memory are intentionally deferred to the isolated Windows CI runner. No production default or local operator repository is modified.
