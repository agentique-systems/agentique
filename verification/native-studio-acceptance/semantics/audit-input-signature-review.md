# Audit reuse input and producer-output separation

The successful exact oracle for source `a6e1f41d2b549a8be10a79dfa3ec786c090b65b3` proves equivalence, not speedup. On its same Windows runner, command preparation was 219.531 s versus the baseline's 161.497 s and the current independent cold restore's 163.268 s. All three evaluated 717 producer subjects. The command retained 366 audit subjects but reused zero checks, evaluating the remaining 425 subjects in 50.002 s. Its 31.030 s checkpoint and 28.556 s rebind signature costs account for the candidate regression. No true incremental wall-time win has been established by that result.

Read-only diagnosis found that producer checkpoint signatures intentionally backpropagate every derived output fingerprint to each immediate supporting input. A lost detached output must make its producer run again even when all input values are unchanged. Using that same fingerprint for an audit also invalidates an unrelated query of a common input when a different, unread output appears or changes. Ordinary query reads do not have that producer-output-retention obligation. The integration lead separates these fingerprint purposes while retaining the original producer behavior, incoming carriers, local proof/search/contribution content, exact immutable mount guard and current closure checks.

The query read contract permits this separation only with complete positive evidence:

- `queries.rs::fact_with_search_sharing` retains the actual derived root in `canonical_dependencies` before expanding its proof. Association projections retain canonical occurrence facts.
- Recursive proof inputs are retained in `positive_dependencies` and `fact_origins`; they are not flattened into `canonical_dependencies`. The existing `shared_search_expansion_matches_eager_public_evidence_exactly` regression explicitly distinguishes those sets.
- `selected_reference_fact` can replace a broad aggregate fact with exact append evidence. It records `OrderedReferenceContribution { element, property, target }` and each contribution's proof/searches. Audit fingerprints still include contribution bytes at the owner and target.
- Ordinary `property` reads retain effective property and inverse/incoming searches. Absent reads and provider searches remain independently checked. Standard-library identity reads already map to fixed context inputs; they are not a global-invalidation cause.
- SysML observations call `canonical_fact_evidence`. The shared authored audit dispatcher observes the primary KerML answer, supporting query/name answers and canonical observations for its 29 applicable operation families.
- An authenticated dependency seals historical proof expansion at its immutable root. The exact dependency allocation guard remains necessary; equal publication IDs alone cannot substitute a new mount.

The collector change therefore adds expanded `positive_dependencies` to its existing canonical-root and search reads. It also refuses private producer-mode answers, which intentionally retain compact rather than fully expanded positive evidence. This strengthens the audit reuse premise; it does not weaken negative searches or closure acceptance.

Three new focused regressions were added to `tests/unit/closed_query_audit.rs`:

1. An unread derived consumer can disappear, change value, proof or computation search, or be newly added without invalidating an unchanged anchor query. The actual anchor query evidence is compared exactly after substituting only the receiving context. A query that read that output must be invalidated in every change case.
2. A derived chain's immediate root and provenance IDs remain equal while a transitive declared input changes. Canonical roots contain only the outer fact, expanded positives include the changed input, and reuse must fail.
3. A Complete compact producer-mode answer over the same context cannot establish a reusable authored-audit receipt.

Both changed collector/test files passed targeted `rustfmt --edition 2024` and whitespace checks locally (exit 0). The integration lead owns compilation and focused test execution, followed by a new independent real command/cold oracle. These regressions and the code review are not a measured speed claim. If query-bearing reuse remains zero, bounded rejected-read IDs and global-versus-local rejection reasons are the next diagnostic; incoming signatures are still deliberately conservative.

The subsequent independent review found a mixed-mode edge case: ordinary `QueryResult::merge_evidence` could absorb a compact producer answer without retaining that compact-mode marker. The integration lead assigned the contract fix to the independent reviewer. The transitive audit regression now also wraps a producer root in an ordinary answer through that public merge, checks the sticky marker, and rejects the incomplete positive-read receipt. The shared SysML audit dispatcher explicitly observes its main answer and every supporting query, supporting name and canonical observation, so the guard also applies to those nested channels.

For the next verification oracle, `AGENTIQUE_AUDIT_REUSE_TRACE=1` enables one `SOURCE_AUDIT_REUSE_TRACE` JSON record per authored audit. It distinguishes missing parent/audit/subject receipts, static SysML or KerML contract rejection, exact dependency mount rejection, invalid or foreign read contexts, global searches, bounded changed reads, missing closure witnesses, and preserved reads. First-rejection counts cover the whole audit population. Diagnostic samples contain at most 16 previously checked rejected subjects, each with at most eight changed read identities, accepted-dependency classification and names capped at 160 characters. These diagnostics do not change reuse predicates or grant reuse; the accessor is compiled only with the verification feature. Separate regressions compare reported reasons to the existing decision and enforce both sample limits.
