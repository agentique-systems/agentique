# Existing-world acceptance work

Grounding: inspected real-run06 gallery 04-requirements-world.png and
06-history-diff.png, then the projection/layout/native code. The requirement
appeared as a package ownership chain and the comparison as a dense mixed graph
with clipped names. These are observations of the real self-model gallery, not
fresh acceptance results.

Changes:

- Requirements projects direct obligation detail and exact modeled subject and
  verification paths without promoting an incoming package owner to engineering
  context. The subject feature and its architecture type stay separate canonical
  identities and edges. Metaclass/relationship-based lanes label Requirements,
  Subjects, System/Part, Satisfaction declarations, Verification, and Owned Detail;
  absent roles are not fabricated. A selection command opens the bounded
  requirement neighborhood of a requirement or architecture element.
- Diff defaults to Structure review. Relationships, Requirements and All modes
  retain one exact revision pair and all canonical change records; only review
  and visible edges change. Hidden-category edges cannot receive pointer hits.
  Removed targets keep their old revision. Next/Previous change and Focus changed
  owner make the existing owner groups navigable. Group focus now preserves at
  least 68% scale where possible. Filtered summaries use a single replacement
  cache per panel, with exact source review identity.
- History cards use recorded edit intent, reliable creation metadata and branch
  heads. Generic imports use exact changed source paths/counts, explicitly labeled
  as source changes. Comparing a chosen same-project revision to the current
  revision and returning to the default branch head are visible operations.
- Inspector names and relation/feature links wrap within the panel. Full names
  remain available in tooltips and a Copy full name context menu.

Integration dependency: interaction commit 4e0d3ffc adds remember_location();
the new requirement and comparison navigation invokes it before leaving context.
No language acceptance contract, cache authority, validation or canonical data is
changed. Satisfaction/verification link presence is explicitly not evaluation.
