The [real-run03 comparison](../real-run03/gallery/06-history-diff.png) is not a useful default. The [capture sidecar](../real-run03/gallery/06-history-diff.json) records 159 projected nodes, 130 scene nodes, 425 projected edges and a camera scale of `0.083043836`. The screenshot shows an anonymous horizontal strip and `+17 added`; it does not explain which architecture changed. This is real accepted-runtime data, baseline `8dcfb224-55e6-4d0d-ac3a-84fcfffb9a46` compared with parent `a0ce9ecb-728a-40ce-87b5-88f8cbc84105`, frame 76965. The capture retains the after projection and camera/layout, not the entire before-side DTO. No new semantic consumer was run to recover additional data for this review.

## Ranked criticism and change

1. **P1: distant changes shrink one another into an unreadable strip.** The new `focus_changes()` helper chooses a recorded-owner change group and frames nearby changed objects in existing scene coordinates. It prefers the existing selection's group. Greedy inclusion keeps the proposed fit at or above 0.42 scale when adding distant context, and caps close-up scale at 1.2. The existing owner header is included when it fits. A large container uses its existing header region as context instead of its full envelope. This is a bounded local camera choice, not a new layout or a claim that every changed relationship endpoint fits. The status explicitly reports nearby context for *x of y visible changes*. `Fit entire comparison` retains the ordinary full-scene fit.
2. **P1: counts do not identify the changed architecture.** A compact `Design changes` review names actual objects and relationships, groups them by original canonical owner identity, prioritizes authored object changes, and provides all groups/all entries beyond its three-row preview. Relation groups explicitly use source-owner context; an unavailable source is labeled outside the view, never inferred to be a top-level object. Names, rename details and owner transitions come only from the exact before/after DTOs. No structural impact or causal consequence is invented. Counts describe the supplied view pair, not a complete semantic-diff claim for the whole repository.
3. **P2: previous Focus changes ignored port-only and relationship-only changes.** The new helper resolves exact scene Port and Edge targets in addition to nodes. Removed objects and relationships retain their before revision. A wide relationship may focus one endpoint's nearby context; its other endpoint and all exact data remain in the comparison. Selecting a change row uses the existing revision-bound `select()` path. Merely focusing changes preserves selection, binding, candidate phase and all model/projection content.

## Boundaries and integration

The implementation lives in `studio-native/src/history.rs`, with a module registration and a small panel hook. It does not edit `app.rs`, `actions.rs`, `updates.rs`, `viewport.rs` or scene construction. Parent integration replaces the old FocusChanges union-fit body with `self.focus_changes()` and schedules initial comparison focus after the viewport has measured its actual dimensions. Explicit full fit remains separate. The parent also owns identical before/after scene-presentation filtering and suppresses temporary loaded-neighborhood narrowing during Diff; this avoids treating presentation omission as removal. The ignored `Show loaded view` control is hidden during Diff here.

Review requires an exact matching ViewDefinition and matching scene-after revision. Only scene targets with the matching individual original revision are actionable. Unavailable changed items remain named but disabled for scene selection. One presentation cache slot is fenced by runtime epoch, binding, both revision IDs, exact view definition and successful scene generation; it avoids recomputing the whole change list every repaint without accumulating per-revision payloads. Full canonical before/after DTOs, removed ghosts, scene coordinates and semantic authority remain unchanged.

The follow-up indexes canonical before/after nodes and scene identities once per review/focus build, replacing per-change full-array endpoint/owner/target searches. This removes quadratic lookup work without changing record equality or claiming a measured wall-time gain. A selected canonical owner can focus its changed children; Node/Container presentation targets with the same canonical identity resolve consistently. A successful explicit runtime-open request clears old requested/deferred view intent and pending change focus, using the parent's new app fields.

## Checks and remaining qualification

Four regression groups cover: removed-element revision and mismatched-lens/scene rejection; actual port-only and relationship-only focus with stale-target rejection; widely dispersed changes staying readable without moving any scene object or losing ghosts; and actual StudioApp focus preserving binding, ghost selection, candidate phase and both exact DTOs while doing nothing in Current/Candidate mode. These are explicit DTO/interaction tests, not substitute real semantic acceptance.

`checks/native-history-change-focus-{format,diff}.json` records formatting and diff checks. Builds and semantic/runtime consumers were deliberately left to the parent's serialized gate. **Integrated tests and a new real comparison screenshot remain required.** The new screenshot must show readable architecture names, a useful local change context, discoverable distant groups, and a usable full-comparison escape. History/Diff is not accepted merely because the helper exists. The historical failing screenshot remains unchanged.
