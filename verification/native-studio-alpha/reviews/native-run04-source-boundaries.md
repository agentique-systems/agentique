# Native run 04 source boundary review

This independent review read the integration worktree while the integration lead ran native tests. The reviewed changes became `bb4a76631d39696d07bbf898dd81f44851ad4ffa`; the subsequent dirty change that defers change-group camera framing to the viewport was also inspected. No build, runtime consumer, source mutation, or native acceptance run was performed by this reviewer. Findings below describe the observed source, before the integration lead's follow-up fixes.

## Ranked corrections

All are presentation correctness issues (P2), not evidence of a semantic authority bypass.

1. **Candidate dependency scope differs from current revision scope.** `actions.rs`, `Dependencies`, creates `ViewDefinition::semantic_graph()` for `candidate_view` without assigning `DependencyNeighborhood`. The current-revision branch calls `StudioPlatform::dependencies`, which does assign it. Consequently the candidate branch can still traverse a containing Package into unrelated siblings. Assign the explicit dependency scope to the candidate request too; test both paths without replacing actual canonical relationships.

2. **Next hop can shrink a loaded neighborhood.** In `actions.rs`, `ExpandBoth`, a focused live Graph at depth eight reaches the cap, then falls through to local expansion. With `expanded=None`, its seed set is just the selected element, and the newly stored local visibility set contains only one hop. A view displaying eight hops becomes one hop after an expansion command. The same local fallback can shrink a fully visible loaded candidate view. At the query cap, retain the existing view and give an explicit limit status. For a loaded-only expansion, retain already visible IDs; use the explicit One hop command to narrow the view.

3. **Exiting an agent view through a World command loses filter isolation.** The dependency action directly changes `world` to Graph, without saving the current world's filters. For example, change System filters, request Dependencies, then explicitly open System: `restore_world_filters` saves the borrowed System preferences as Graph preferences and restores an absent/stale System entry. Exact agent dismissal does restore the saved projection, families and standard-library setting correctly. An explicit-world exit must also preserve the original world's preferences and the independent Graph preferences, rather than treating the temporary lens as a persistent Graph preference.

4. **Explicit Graph intent is discarded during a mutation.** `switch_world` prepares an ordinary one-hop `Neighborhood` definition. `request_projection_definition` takes the mutation-pending branch, discards that definition, rebuilds only the loaded projection, and correctly refrains from issuing a semantic query. If the loaded projection was an agent dependency view, later `definition()` copies `DependencyNeighborhood` back from it. Retain the requested presentation intent separately until it can be queried, or keep the loaded dependency scope explicitly identified; do not suggest that the ordinary Graph request has already been performed.

5. **Port summaries can recreate an explicitly hidden port.** `scene_build::presentation_projection` filters nodes and edges by hidden IDs/local expansion, but leaves retained nodes' `features` unchanged. `studio-scene/src/lib.rs` constructs ports from those summaries in addition to projected port nodes. A port removed from the disposable node list can therefore still be drawn, hit-tested and exposed through AccessKit. Apply the same exact-ID visibility predicate to features in the disposable clone. Preserve the original semantic DTO and its semantic totals.

6. **Show loaded view remains actionable during Diff.** `panels.rs` shows this direct action whenever `expanded` exists. Diff now deliberately ignores that set to retain removed objects. The action consequently changes retained Current/Candidate presentation without changing the visible Diff. Hide or disable it in Diff, consistently with the new shared neighborhood-command guard.

## Boundaries that held on source inspection

- `presentation_projection` applies relationship-family and System Ownership suppression to both comparison inputs. A real removed eligible relationship remains a ghost; an Ownership edge suppressed only for presentation cannot become a false removal. Original projection DTOs remain intact.
- Diff passes no current-only expansion set to either side. This is necessary: restricting the before-side to current IDs would erase real removals, while restricting only the after-side would fabricate removals. The shared command guard rejects local neighborhood edits in Diff. Camera framing of a change group leaves this semantic comparison population unchanged.
- Ordinary live Graph switching explicitly chooses `Neighborhood`, while ordinary reprojection preserves the loaded view's `graph_scope`, depth, hidden IDs, family selection and standard-library setting. The candidate branch and mutation edge cases above are the exceptions requiring correction.
- The new semantic Next hop path requires a live current Graph, no candidate, no pending mutation, and selection equal to the focus. During mutation the fallback uses loaded semantic data and reports that boundary rather than claiming a new query.
- The same `port_visible` predicate governs low-LOD hover remapping, marquee eligibility, native port widgets and their AccessKit names. Actual selected port targets receive a constant-screen-size marker; focused System boundary ports remain accessible at overview zoom. The hidden-feature reconstruction issue above occurs before this consistent renderer policy.
- The real pan driver waits two actual native passes after the dialog and camera settle, sends pointer events, and checks actual camera displacement while mutation remains pending. Its preparation clock and input-hook accounting continue throughout the wait. No direct camera assignment or weaker semantic assertion was introduced. This is preparation for run 04, not evidence that the actual background pan or concurrent Inspector journey has passed.
