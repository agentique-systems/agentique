# Real native inspection during candidate preparation

This follow-up qualifies the new immutable read lane through the ordinary real
journey. It is separate from the retained failed real-run01/real-run02 evidence.
No run or accepted result is claimed here.

After the existing native pan is observed while preparation remains pending, the
driver selects a different authored, source-backed PartDefinition or PartUsage
actually present in the current loaded scene. It uses the same ordinary Explorer
search, native text input and recorded canonical row geometry as other journey
steps. The selected object is not hardcoded to a subsystem that an intentional
overview depth may omit. No app state, response or semantic record is injected.

The request must change after this input. Its actual Inspector must become visible
with the same runtime epoch, baseline project/revision and canonical element while
the mutation request is still pending. The report retains the complete Inspector,
request ID, input/request/response frame observations and application-observed
elapsed times. This establishes visibility before delivery of the candidate result;
it does not measure the semantic worker's CPU completion instant or physical input
latency. Existing native input-hook gap and pan checks remain independently required.

Candidate Working acceptance now fails when this inspection is absent, belongs to
another binding, arrives after the mutation is no longer pending, reuses the create
owner, or has mismatched response identity. A focused counterexample test covers
these failures. No frame count or successful pan substitutes for the Inspector.

The operator's create intent already retains its original owner independently of
live selection. Leaving the newly inspected baseline object selected is therefore
safe; the later candidate journey explicitly selects the added Part and separately
checks its canonical owner. The driver does not reset selection behind the operator.

Formatting and diff checks are recorded. Integrated compilation/tests and an actual
authenticated native journey remain required before claiming concurrency acceptance.
