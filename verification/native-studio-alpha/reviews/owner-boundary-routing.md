# Same-owner connections and readable boundary-port labels

This bounded spatial change is based on `774f065` and addresses the actual [run04 ModelingPlatform port image](../real-run04/gallery/02a-platform-port.png). The old same-owner shortcut crossed the container body before turning outward; the connection ran through workspace/systemsModelingApi cards. Boundary names were also drawn over those children, visually implying the wrong owner despite a correct semantic Inspector.

The scene now evaluates both directions around an exterior rectangle for same-owner endpoints, then a bounded set of wider rectangles when obstacles require it. Top, bottom, left and right endpoints retain their exact positions. Same-port loops remain compact outside the boundary. Parallel relationships retain distinct exterior lanes; the original ViewEdge is copied intact, including relationship/endpoint IDs, revision, family, provenance and direction. If all attempted routes collide, RouteQuality remains Obstructed. No semantic direction or ownership is inferred from route geometry.

An expanded container with one to four distinct projected ports reserves at most two small header rows, with minimum header heights 92 or 116 world units. Counts come from deduplicated actual port identities in projected records/features/proxies, not a summary count. Actual child bounds must leave the header clear before ScenePort advertises its disposable label slot. Ordinary compact cards and dense interfaces retain distributed boundary placement. The renderer centers names in the reserved row; distributed expanded-owner names are outside the body with a short leader. At low zoom, when fixed-size text no longer fits the header row, the exterior placement is used. Long names still use bounded single-line typography and retain the full hover/Inspector name.

No model, source, query, accepted publication or candidate lifecycle changed. Header reservation uses existing hierarchy packing, so it may move local children enough to clear the new row; it does not reorder the complete world intentionally. Rebuilding an unchanged layout must retain every node position.

Source regressions cover: the actual-style 844 by 542 owner with nine child cards and a blocked lower route; all sixteen boundary-side pairs and four same-port loops; distinct parallel relationships and an unavoidable obstruction; one/two/four/five/twenty-four actual ports with deliberately misleading summary counts; exact port identity/revision/owner/unspecified direction and hit targets; unchanged-layout stability; and header/exterior label rectangles at the actual approximately 71% focus scale.

Self-critique: this is not a general global label solver. Dense exterior labels can compete with neighboring objects or the viewport edge, particularly at low zoom. The bounded router can truthfully report Obstructed even when a more elaborate distant path exists. The header change may shift local first-row geometry on first use; that is the deliberate cost of keeping labels out of child cards. The new real screenshot must show that the connector remains traceable and the two labels read as ModelingPlatform ports before closing the visual P1.

Only source formatting and diff checks ran in this worktree. Rust tests, Clippy, performance and real-image qualification are delegated to integration; no runtime or build was started here.

Integration source review caught two defects before compilation: a misplaced side field in the SceneEdge initializer (instead of the modeled-port Endpoint initializer), and a hardcoded 22-unit self-loop return that could become diagonal for staggered 25/28-unit generic anchors. The follow-up places the field on both real Endpoint constructors and uses both endpoints' actual stub lengths for coincident-anchor loops. An additional regression covers all four sides with differing 25/28 and 40/25-unit stubs, exact endpoint/return-stub positions, orthogonality and no owner-interior crossing. This correction is source-reviewed and formatted, with tests still delegated to integration.
