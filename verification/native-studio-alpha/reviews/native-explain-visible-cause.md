# Explain: keep the selected consequence visible

The [actual real-run03 capture](../real-run03/gallery/05-explain.png) fails the causal-diagram product gate: four supporting-fact cards are visible, while the rule and selected consequence lie below the inner scroll viewport. An engineer cannot read the cause and consequence together.

The [capture sidecar](../real-run03/gallery/05-explain.json) records real accepted-runtime data, baseline revision `8dcfb224-55e6-4d0d-ac3a-84fcfffb9a46`, frame 52503, selected derived relationship `048aa6da-28eb-5422-a3ea-64455fee0895`, rule `94707247-8219-4686-d858-3b07bd519c9b`, and 621 evidence dependencies. Its canonical projection contains `repositoryRevisions` (`b6fd9cc1-8936-51c9-8618-b9c7ca2c810a`) — `subsets` → `suboccurrences` (`4ecd65d9-2c98-58c8-b7ac-24f9fcf48086`). The sidecar retains the projection and Explain identity/count, not the complete ExplanationProjection payload; no independent inspection of all 621 dependencies is claimed here.

## Ranked criticism and change

1. **P1: the rule and consequence are clipped.** The previous diagram used all eight supplied evidence nodes to set a 750-point content height, then vertically centered the rule and consequence inside a 350-point scroll viewport. The summary now takes the selected fact's actual incoming rule and only two or three of that rule's actual supporting facts. Three columns fit the available width at 600 points or wider; narrower windows put supporting facts above the rule and consequence. The diagram has no inner scroll area. Normal three-support layout is 252 points tall; two-support wide layout is 164; narrow layout is 268. These are layout dimensions, not measured frame timings.
2. **P2: the conclusion said only `Subsetting : Subsetting`.** For the known binary Subsetting projection, the summary can now name the exact visible endpoints: `repositoryRevisions subsets suboccurrences`. This requires matching projection/edge/endpoint revision, relationship ID, rule and origin, exact Subsetting kind/family, direction, both endpoints, and a single matching projected edge. A property fact, other relationship kind, missing endpoint, or mismatched scope retains the original proof label.
3. **P2: the rule name reads like an implementation identifier.** Only the verified `checkOccurrenceUsageSuboccurrenceSpecialization` gets the display name `Suboccurrence specialization`. The rule is present in [the producer implementation](../../../crates/sysml-semantics/src/producers.rs) and [the pinned normative inventory](../../../standards/sysml-semantic-coverage.json); native code does not reproduce its applicability checks or infer property values. Unknown names remain exact. When no recorded rule name is available, the card says `Semantic derivation rule` and retains the exact producer identity in evidence.

## Truth and disclosure

Every arrow still comes from an existing proof edge; unrelated nodes never become causes because of list order. The selected consequence has a stronger border and retains its canonical proof label/ID on hover. The summary explicitly reports how many supporting facts it shows out of those available. The separate partial-proof notice preserves the full recorded dependency count. `Evidence · exact facts and rule` and `Advanced · publication context` retain their existing contents and exact DTOs; the summary does not mutate or further truncate the underlying projection. The current service's existing eight-dependency projection limit remains unchanged and is not presented as all 621 dependencies.

Three focused regression groups were added: all summary cards fit without overlap at 720/600/599/320 logical-point widths with eight supplied supports and 621 recorded dependencies; disconnected rules cannot become causes; and ten revision/identity/endpoint/kind counterexamples plus property facts reject the readable relationship substitution. Existing tests continue to require unknown rule names and exact evidence preservation.
